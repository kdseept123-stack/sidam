# 네이버 블로그 작성 지원 프로젝트

방문한 가게(맛집/카페 등) 사진을 바탕으로 네이버 블로그 포스팅 초안을 작성해주는 작업.
사용자는 폰으로 사진만 올리고, 초안 작성은 Claude가 담당한다.

현재는 **일반 방문 후기**로 시작. 추후 **체험단/협찬** 후기도 다룰 예정 — 그때는
공정거래위원회 규정상 "경제적 대가를 받았음" 문구를 본문에 반드시 명시해야 한다 (진행 시 사용자가 알려줌).

## 워크플로우

1. 사용자가 폰으로 구글 드라이브에 **가게이름을 폴더명**으로 폴더 생성 후 사진 업로드
   - 사진 순서는 **파일명 숫자(IMG_XXXX) 오름차순 = 글 구성 순서**로 취급 (외관 → 메뉴판 → 음식 순 등 자연스러운 방문 흐름)
     - ⚠️ 구글 드라이브 업로드 시각(createdTime)은 실제 촬영 순서와 무관하다 (파일 크기 등 다른 기준으로 정렬되어 반환될 수 있음) — 절대 createdTime을 순서 기준으로 쓰지 말 것
   - 파일명에 정확한 가게이름이 들어있으면 주소·영업시간·전화번호 등 기본정보 확인에 활용
   - 사진은 **HEIC 형식**(아이폰 기본)으로 업로드됨 — Drive 도구가 HEIC를 직접 읽지 못하므로, 다운로드 후 로컬에서 JPEG로 변환(`pillow-heif`)한 뒤 확인한다
2. 사용자가 "오늘 [가게이름] 써줘" 라고 요청하면 시작 (자동 감시 아님, 명시적 요청 기반)
3. Claude가 할 일:
   - 해당 구글 드라이브 폴더의 사진들을 시간순으로 확인
   - 가게 기본정보(주소/영업시간/전화번호)는 가게이름으로 **웹검색해서 확인**. 부족하면 사용자에게 확인 요청
   - 키워드는 **웹검색으로 추정** (블랙키위·네이버 광고 키워드도구 등은 직접 접근 불가). 정확한 검색량/발행량 숫자 대신 "더 구체적이고 경쟁이 낮을 것 같은 후보" 방향으로 제안
   - 아래 [글쓰기 원칙]에 따라 제목 후보 3개(+추천 1개), 태그, 사진 순서에 맞춘 본문 초안 작성
4. 완성된 초안은 **같은 구글 드라이브 폴더에 구글문서로 생성**
5. 사용자가 마지막에 직접 추가하는 부분 (초안에 빈 영역/표시로 남겨둘 것):
   - 개인적인 감상·평가
   - 방문 계기나 에피소드
   - 방문자 리뷰 답변용 멘트 등 기타
6. 사용자가 직접 네이버 블로그에 복사 + 사진 업로드해서 발행 (현재는 수동 발행)
   - **추후 확장**: Playwright 기반 네이버 자동 로그인/발행. `../splace/naver_login_setup.py`, `naver_auth.json`에 유사 로그인 자동화 흔적 있음(다른 프로젝트지만 참고 가능)

## 글쓰기 원칙 (『최광자 블로그 인플루언서 수익화 백과사전』 기반)

### 키워드
- 키워드 선정 시 우선순위: **검색량은 높고 발행량(경쟁 문서 수)은 낮은** 키워드
- 키워드 사용 = ① 본문에 키워드에 대한 설명을 자세히 기술 ② 제목에 포함 ③ 태그에 포함 — 셋 다 충족해야 함
- 하나의 제목/글에는 키워드 1개, 많아도 4~5개까지만 공략 (너무 많은 키워드를 욱여넣지 말 것)
- 같은 단어를 제목에서 중복 사용하지 말 것 (예: "카카오뱅크와 카카오미니카드, 카카오톡" → 어뷰징으로 판단될 수 있음)
- 블로그 주제와 무관한 실시간 이슈성 키워드는 잡지 않는다

### 제목
- 길이는 **21자 이내**
- **메인 키워드를 제목 맨 앞에** 배치, 키워드가 2단어로 이루어져 있으면 **띄어쓰지 말고 붙여서(연속으로)** 사용
  - 좋은 예: "종부세 계산기 – 종합부동산세 고지서"
  - 나쁜 예: "종부세 고지서 받으셨나요? 종합부동산세 계산기" (키워드가 앞에 없고 쪼개짐)
- 사람이 클릭하고 싶게 만드는 요소도 함께 고려 (택 1~2개 조합):
  - 보상형 ("~하는 5단계 방법")
  - 손실회피형 ("~하지 않으면", "모르면 손해보는", "당신만 모르는")
  - 구체적 수치 제시 (막연한 표현보다 숫자)
  - 타겟 명확화 (누구를 위한 글인지 드러내기)

### 본문
- **제목과 본문의 의도를 반드시 일치**시킬 것 — 제목의 키워드에 대한 실제 정보가 본문에 있어야 함 (이탈률 = 저품질 원인)
- 글자수/사진 장수를 기계적으로 채우는 것(예: 무조건 1500자+사진 20장)이 목적이 아니라, **키워드에 대해 충분한 정보를 담는 것**이 목적
- **사진 중복 사용 금지** — 이 블로그에서 한 번이라도 쓴 사진 재사용 금지, 인터넷에서 가져온 사진 사용 지양
- 상업적 외부링크 반복 사용 지양, 낚시성 링크 금지

### 발행 후
- **발행 후에는 제목/본문을 수정하지 않는다** (특히 메인 키워드 변경은 거의 100% 노출 실패로 이어짐). 정말 노출이 안 될 때만 예외적으로 최대 1회 수정 고려
- 카테고리 이동은 "글 관리 → 이동" 기능으로 처리 (재발행 방식 금지 — 어뷰징으로 판단될 수 있음)

## 사진 확인 방법 (실행 노트)

- `mcp__claude_ai_Google_Drive__download_file_content`로 HEIC 사진을 받으면 base64 용량이 커서 거의 항상 "exceeds maximum allowed tokens" 에러가 뜨지만, 전체 내용은 `tool-results/...txt`(JSON: `{content, id, mimeType, title}`)에 저장되어 있다. 이 JSON을 직접 읽지 말고, Bash/Python으로 `content`(base64)를 디코드해서 `.heic`로 저장한 뒤 `pillow-heif`로 `.jpg` 변환한다.
- 변환된 JPEG가 여러 장일 때는 개별 Read로 다 보지 말고, PIL로 3열 그리드 콘택트시트(파일명 라벨 포함)를 만들어 몇 장으로 묶어서 확인하면 훨씬 효율적이다.
- `pillow-heif`가 없으면 `pip install pillow-heif`로 설치 (1회성, 이미 설치됨).

## 결과물(구글문서) 구성 순서

1. 제목 후보 3개 (추천 1개 표시)
2. 태그 목록
3. 기본 정보 (주소/체크인아웃/전화/조식·수영장 시간/네이버플레이스 링크 자리)
4. **다른 방문자 후기에서 찾은 꿀팁** — 발행 전에 WebSearch/WebFetch로 같은 장소를 다룬 기존 블로그·커뮤니티 후기를 찾아서, 거기 나온 실용 정보(예약 팁, 좌석 요청법, 대여 품목 등)를 정리해 이 섹션에 추가한다. 사용자의 실제 경험과 다르면 사용자가 고치도록 안내 문구를 넣는다.
5. 본문 (사진 순서에 맞춰 구성, 사진 삽입 위치는 파일명이 아니라 **사람이 바로 알아볼 수 있는 설명**으로 표시 — 예: "[체크인 사진]", "[욕실 사진 2장]". 사용자가 폰 갤러리에서 사진을 찾을 때 파일명을 볼 일이 없기 때문)
6. "✍️ 여기에 직접 추가" 섹션 (감상/에피소드/리뷰 답변 멘트용 빈 자리)

## 사진 삽입/발행 방식

- 사진을 구글독스 안에 실제로 임베드해서 통째로 복사-붙여넣기 하는 방식은 시도했지만 실패: 이미지를 문서에 넣으려면 base64로 인코딩한 거대한 텍스트를 도구 호출 파라미터에 직접 담아야 하는데, 사진 몇 장만 넣어도 용량이 감당 안 됨. 이 방식은 다시 시도하지 말 것.
- 대신 텍스트(구글독스에서 복사)와 사진(사용자가 폰 갤러리 또는 PC 폴더에서 직접, 혹은 파일탐색기에서 복사)을 각각 따로 붙여넣는 방식을 기본으로 안내한다.
- 구글독스 MCP 도구는 파일 "생성"만 가능하고 "수정"은 불가능하다 — 초안을 고칠 때마다 같은 제목으로 새 문서를 만들고, 사용자에게 이전 버전을 직접 삭제해달라고 안내한다.
- `search.naver.com`, `map.naver.com`, **`blog.naver.com`(직접 글 링크 포함)** 등 네이버 도메인은 전부 WebFetch로 접근이 차단되어 있다 — 사용자가 특정 블로그 글 URL을 줘도 열어볼 수 없다. 이 방법은 다시 시도하지 말 것.
  - 네이버 상위노출 블로그를 참고하고 싶으면: (a) 사용자가 글 내용을 직접 복사해서 붙여넣어주거나 (b) 스크린샷을 찍어 보내주는 방법만 가능하다.
  - 네이버플레이스 링크처럼 네이버 자체 데이터가 필요하면 사용자가 폰에서 직접 복사해서 알려주도록 요청한다 (URL을 추측해서 주면 안 됨).
  - 일반 WebSearch로도 blog.naver.com 글은 거의 색인되지 않아 검색으로도 안 걸린다. 대신 다이닝코드·마일모아·티스토리 등 일반 웹에 걸리는 후기/커뮤니티 글은 검색으로 찾아 참고할 수 있다.
